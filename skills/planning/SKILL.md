# Planning

Планирование смотрит вперёд и назначает следующие задачи. Работу оно не выполняет.

## Пререквизит

Найди принятый отчёт `reports/ГГГГ-WNN-retro.html` за прошедшую неделю. Если ретро не проведено или не принято, остановись и предложи сначала `retro`.

## Граница

Планируй только задачи этого штаба. Источник состояния — `TASKS.md` и `tasks/<slug>/task.md`. HTML-план — представление выбранных результатов и ссылок. Задачи заводит и обновляет `manager`.

## Этап 1. Собрать вход

Прочитай:

1. `ME.md` и `MAP.md` — что сейчас главное для владельца и отделов;
2. принятый отчёт ретро и решения по незавершённому;
3. `TASKS.md`: задачи `в работе`, `ждёт меня` и «Входящие»;
4. последнее принятое изменение правил.

Задачи `готово` не являются обязательствами новой недели. Открытую задачу не переноси автоматически — используй решение из ретро.

## Этап 2. Выбрать результаты недели

Результат недели — проверяемое состояние, а не действие.

Плохо:

```text
Поработать над портретом ЦА.
```

Хорошо:

```text
Портрет ЦА собран из 20 исследованных компаний, каждая цитата ссылается на materials/, владелец принял файл.
```

Предложи 1–3 результата на основе фактов, затем задавай владельцу по одному вопросу о том, чего нет в источниках. Больше трёх результатов не бери: лучше один доведённый, чем пять начатых.

Для каждого принятого результата зафиксируй:

- что должно стать правдой;
- как это проверить;
- к какой дате;
- какая задача владеет состоянием;
- что сознательно не входит в неделю.

## Этап 3. Назначить задачи

Передай `manager`:

- для существующей задачи — обновить критерии приёмки и записать в журнал «Следующий шаг»;
- для новой работы или строки из «Входящих» — завести задачу по шаблону;
- для результата, где больше трёх шагов, — пометить, что сначала нужен `grill-with-docs` → `to-spec` → `to-tickets`.

Не создавай вторую задачу для той же работы. Не выполняй следующий шаг во время планирования.

## Этап 4. Сохранить HTML-план

Создай:

```text
reports/ГГГГ-WNN-plan.html
```

План содержит:

- результаты недели и как их проверить;
- раскладку по дням, если даты выбраны;
- ссылки на `task.md`;
- сознательно исключённую работу;
- ссылку на отчёт ретро.

Семантический HTML, встроенный CSS, без сборщика. Полное состояние задач не копируй.

В отчёт ретро добавь только ссылку на новый план, остальное в нём не переписывай.

## Этап 5. Проверка и приёмка

Проверь:

- каждый результат проверяем и связан с задачей;
- дублей задач нет;
- даты не в прошлом;
- `manager` записал следующий шаг в каждую выбранную задачу;
- ссылки ретро ↔ план работают в обе стороны;
- ни одна задача не выполнялась во время планирования.

Покажи план владельцу. После приёмки сессия планирования закончена. Рабочий день начинается с `daily`.

## Запрещено

- планировать без принятого ретро;
- превращать все идеи и «Входящие» в обязательства недели;
- выполнять задачи внутри planning;
- хранить состояние только в HTML;
- писать в `TASKS.md` и `task.md` в обход `manager`;
- молча переносить незавершённое.
